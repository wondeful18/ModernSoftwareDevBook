# 前言 · 从一次工具调用开始

把一条写代码的指令交给模型，屏幕上会出现一段文字。把同一句话交给编程代理，磁盘上可能真的多一个文件。第一章追着这次写入走一遍，看看模型返回了什么、客户端实际执行了什么，以及拿哪条回执可以确认结果。后面的章节把同样的追问带到一个连续的小项目。代理准备了改动，怎样知道它符合规格？团队怎样评审、发布，出了问题又怎样回到上一版？

## 贯穿全书的 Taskboard

Taskboard 是一个展示本地任务清单的 Python 命令行工具。种子数据有三条任务，ID 分别为 101、102、103，状态取 `open` 或 `done`。第 1 章用内存查询复现一次完整的工具调用，第 2 章给列表筛选写规格，第 5 章把它写成可运行的 CLI。你会在第 6 章故意改坏排序，亲手找出测试盲点，再把这处改动交给后台代理和发布流程。

从第 2 章开始，将你每章的实践产物保存在自己的实验目录，例如 `taskboard-lab/`。下面的布局会随练习逐步长出来。

```text
taskboard-lab/
├── taskboard/
│   ├── domain.py       # 状态筛选与排序
│   └── cli.py          # 参数、输出及退出码
├── tests/
├── docs/               # 规格、决策与交付证据
└── .agents/skills/     # Skill 示例位置，以客户端约定为准
```

## 怎么读

1. **先跑一遍。** 第 1 章只需 Python 3，实验使用固定输出的模拟模型。第 4、8 章的 Git 练习需要 Git。
2. **挑一个变量再跑。** 更换筛选状态、减少执行预算，或者改一处代码触发回归。记录输入、预期和实际结果。
3. **留下一份能交接的证据。** 测试输出、清晰的差异或运行记录都可以。后续练习所需的前置工作会在各章开头或步骤中说明。没有代理客户端时，可以手工扮演各角色并用同样的标准验收。

全书一章对应一周。相关章节会交代课堂讲的是什么，官方作业让学生实际做什么，以及 Taskboard 练习能验证什么。你可以从第一讲的真实模型代码看全貌，再用离线实验慢放关键步骤。书中涉及工具和协议的部分附有原始资料，按客户端和协议版本核对实现细节。 [课程官网](https://themodernsoftware.dev/)
