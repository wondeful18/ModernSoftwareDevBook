# 前言 · 从一次工具调用开始

假设你收到一张工单：“把任务板整理一下。”有人会先问哪个视图出了问题，也有人会先改代码。交给编程代理时，同样的选择还会出现在读取哪些文件、调用什么工具，以及由谁决定可以交付。每章从一个具体场景切入，画出数据与控制流，再用练习核对它们是否按预期工作。

## 贯穿全书的 Taskboard

Taskboard 是一个展示本地任务清单的 Python 命令行工具。种子数据有三条任务，ID 分别为 101、102、103，状态取 `open` 或 `done`。第 1 章在内存里演示工具调用，第 2 章为列表筛选写规格。后续章节把这项改动带进可回归的仓库、评审和交付流程。

从第 2 章开始，将你每章的实践产物保存在自己的实验目录，例如 `taskboard-lab/`。下面的布局会随练习逐步长出来。

```text
taskboard-lab/
├── taskboard/
│   ├── domain.py       # 状态筛选与排序
│   └── cli.py          # 参数、输出及退出码
├── tests/
├── docs/               # 规格、决策与交付证据
└── .agents/skills/     # Skill 示例位置，以客户端约定为准
```

## 怎么读

1. **先跑一遍。** 第 1 章只需 Python 3，实验使用固定输出的模拟模型。第 4、8 章的 Git 练习需要 Git。
2. **挑一个变量再跑。** 更换筛选状态、减少执行预算，或者改一处代码触发回归。记录输入、预期和实际结果。
3. **留下一份能交接的证据。** 测试输出、清晰的差异或运行记录都可以。后续练习所需的前置工作会在各章开头或步骤中说明。没有代理客户端时，可以手工扮演各角色并用同样的标准验收。
